API endpoints
- POST /api/transactions  -> creates a transaction (server assigns UUID and status=PENDING)
- GET  /api/transactions/{id} -> fetch transaction by id
- PATCH /api/transactions/{id}/status -> update status (only PENDING -> COMPLETED/FAILED)
- GET  /api/customers/{customerId}/transactions -> list customer transactions

Validation & business rules
- customerId: required, non-blank
- amount: required, numeric and >= 0.01 (no zero/negative amounts)
- currency: required, 3-letter code; input normalized to UPPERCASE before persisting
- type: required (DEBIT or CREDIT)
- id: generated by server (UUID)
- initial status: server forces PENDING on create (client-supplied status ignored)
- status transitions: only allowed from PENDING to COMPLETED or FAILED; other transitions rejected
